# model-layout

Отдельная Python-утилита для переключения размещения моделей. Не импортирует
`llm_proxy` и не запускает собственного сервера. Каталог можно перенести целиком
в отдельный репозиторий. На координаторе нужны Python 3.10+, PyYAML и OpenSSH;
на узлах — Python 3, PyYAML для proxy-узлов, пользовательский systemd.

## Установка и команды

Штатный координатор — **Aurora, 192.168.0.61**. Установленные файлы:
`~/.local/share/model-layout/`, команда `~/.local/bin/model-layout`.
SSH из Aurora к `mirmik@192.168.0.173` и `mirmik@192.168.0.76` должен работать
без ввода пароля; проверка ключей хостов OpenSSH остаётся включённой.

```sh
model-layout status
model-layout plan flash
model-layout switch flash --dry-run
model-layout switch flash
model-layout switch 27b
model-layout plan flash-ring
model-layout switch flash-ring
model-layout switch 27b-ring
model-layout recover
```

`-c /path/layouts.yaml` перед командой выбирает другую конфигурацию.
`plan` и `--dry-run` проверяют узлы, файлы, runtime, профили, службы и доступы;
ничего не записывают и не останавливают. `status` показывает фактическое состояние
моделей/маршрутов/персонажей и последний журнал. Повторный `switch` уже полностью
применённого режима ничего не перезапускает.

| Режим | Aurora .61 | GPU .173 |
|---|---|---|
| flash | flash-next-strata | gemma4-26b-heretic, stt-gigaam |
| 27b | gemma4-26b-heretic, stt-gigaam | qwen3.8-27b-uncensored-q4-mtp |
| flash-ring | flash-next-strata-ring | gemma4-26b-heretic, stt-gigaam |
| 27b-ring | gemma4-26b-heretic, stt-gigaam | qwen3.8-27b-uncensored-q4-mtp-ring |

Конфигурация включает определения недостающих runtime ring, Gemma и GigaAM.
Они добавляются при первом переключении; существующие определения не затираются.
Файлы моделей должны быть подготовлены заранее: утилита их не скачивает.

## Постоянные адреса

Клиенты продолжают использовать `https://192.168.0.61:8090`:

- Chat: `/v1/chat/completions`, model `gemma4-26b-heretic`.
- STT: `/stt`, runtime `stt-gigaam` (обычный `/stt` также подходит при единственном STT).
BGE исключён из всех режимов: он остановлен, autoload/on_demand отключены,
его маршруты удаляются. Имя оставлено в `managed` только для запрета автоматического
запуска при переключениях. Эмбеддинги этим размещением больше не предоставляются.

В режимах 27b и 27b-ring маршруты ведут на локальные порты runtime, в режимах flash и flash-ring — на
HTTPS-прокси .173 с существующим `hosts.remote-173`. Маршруты на .173 также переключаются: в flash они ведут на локальные runtime,
в 27b — на .61. Это исключает взаимную пересылку между прокси.
Локальный маршрут не идёт
на самого себя через порт 8090, поэтому цикла нет. В конфигурации сохранён
действующий способ доступа к self-signed HTTPS .173 (`tls_verify: false`).
Секреты берутся из конфигураций на узлах и не копируются в конфигурацию утилиты.
Старый маршрут Qwen 27B на .61 не меняется; в flash эта конкретная модель недоступна.

Проверка готовности перед возобновлением работы идёт по локальным health URL
каждого целевого runtime через SSH. Общего `/health` прокси для этого недостаточно.
Постоянные маршруты вступают в силу при первом успешном `switch`, включая `switch 27b`.

## Nemor

На .76 переключаются только явно перечисленные персонажи:

| Персонаж | 27b | flash |
|---|---|---|
| atom | model-atom | model-flash-strata |
| atom-subagent | model-atom | model-flash-strata |
| tet | model-tet | model-flash-strata |

В `flash-ring` все три персонажа используют `model-flash-strata-ring`, в `27b-ring` —
`model-27b-ring`. `nodes.nemor.character_settings` переключает вместе с профилем:

- ring: `context_management=runner`, `send_session_id=true`, timeout 1800 s;
  размер окна 131072 у Flash Strata и 114688 у 27B;
- обычные режимы: клиентское управление контекстом (поле `context_management`
  удаляется), окно 131072, timeout 600 s у Atom/подагента и штатный у Tet.

Значение `null` в настройках удаляет поле и возвращает default приложения.
Каждый режим задаёт один и тот же набор управляемых полей, чтобы переход назад
не оставлял настройки ring. Эти поля участвуют в проверке no-op и откате.
`inference_settings` задаёт proxy timeout 1800 s в ring-режимах и возвращает
штатный timeout в обычных режимах. Остальные персонажи и поля сохраняются.
Список расширяется в `nodes.nemor.characters`. Перезапуск Nemor применяет выбор
к заново загруженным сессиям, без изменения истории и исходников приложения.

Сначала останавливаются голосовой клиент и координатор, затем ожидается отсутствие
обрабатываемых сессий и незавершённых фоновых задач, после чего останавливается
Nemor. Таймаут ожидания — 300 секунд. Возобновляются только службы, которые
работали перед переключением.

**Граница первой версии:** пауза затрагивает весь процесс Nemor, в том числе
персонажей с другими моделями. У существующего API нет атомарного запрета новых
задач: прямой запрос или задание scheduler между проверкой idle и остановкой
может быть прервано. Во время переключения не отправляйте новые задачи напрямую.
Бесшовная пауза требует отдельного maintenance/drain API в Nemor.

## Порядок переключения и восстановление

1. Полный preflight до изменений; отказ при работающих или автоматически
   запускаемых runtime вне управляемого списка.
2. Локальный `flock`, удалённые блокировки владельца транзакции, резервные копии
   конфигураций и снимок состояния служб/моделей на всех узлах.
3. Пауза Nemor, остановка обоих proxy-сервисов (systemd останавливает их процессы).
4. Изменение только управляемых флагов запуска, маршрутов Gemma/STT, proxy timeout, `llm_profile`
   и перечисленных настроек контекста персонажей. У всех управляемых runtime `on_demand=false`;
   `autoload=true` только у размещённых в выбранном режиме.
5. Запуск обоих прокси, проверка всех целевых моделей, запуск Nemor и голоса.

Новые запросы к proxy во время рестарта могут получить ошибку подключения;
очередь запросов эта утилита не предоставляет. Ручной запуск несовместимой модели
через панель прокси остаётся возможным: утилита управляет плановыми переключениями,
а не является GPU admission controller.

При обычной ошибке выполняется автоматический откат. Восстанавливаются исходные
файлы и ранее работавшие модели, включая запущенные вручную с `autoload=false`.
Если не удаётся остановить любой proxy, обратный запуск моделей не начинается.
При недоступном узле или прерывании процесса остаются журнал и блокировки:
устраните причину и выполните `model-layout recover`. Не удаляйте блокировки
и не запускайте второй координатор. `recover` также завершает освобождение
блокировок, если режим уже применён, но SSH оборвался при финальной очистке.

Журнал координатора: `~/.local/state/model-layout/controller/transaction.json`;
история — `history/`. На каждом узле исходные файлы хранятся в
`~/.local/state/model-layout/<transaction-id>/` с закрытыми правами. Резервные копии
содержат секреты исходных конфигураций: не публикуйте их. При изменении файла
посторонним процессом переключатель откажется затирать его во время отката.
После ручного разрешения конфликта повторите `recover`.

Не меняйте YAML-конфигурацию утилиты до завершения транзакции: recovery проверяет
её хеш. Runtime с `autoload=true`, но остановленный вручную, нужно привести в
согласованное состояние перед новым переключением — preflight откажет, чтобы
последующий рестарт не загрузил неожиданную модель.

## Проверки разработки

```sh
python3 -m unittest discover -s deploy/model-layout/tests -v
```

Тесты используют имитацию узлов и временные файлы: порядок остановки/запуска,
no-op, read-only plan, блокировки, откат, сохранение чужих полей и защита от
конкурентных правок. `plan` на реальных узлах не заменяет испытания загрузки
моделей на GPU и генерации через маршруты.

## Проверка на GPU .173

Gemma с параметрами Aurora `-b 2048 -ub 2048` заняла почти всю RTX 3090 Ti и
вызвала OOM у GigaAM. Для .173 закреплены `-b 512 -ub 256`; контекст 32768 и
модуль изображений сохранены. Gemma и GigaAM вместе успешно запущены. BGE
исключён из обоих режимов по указанию пользователя. Переключатель теперь
показывает состояние каждой модели (queued/loading/ready/exited) и начинает
откат при подтверждённом завершении процесса вместо ожидания 1200 секунд.

## Установка ring-профилей

Исходники установленной утилиты сохранены в `llama-ring/deploy/model-layout/`.
Режимы `flash` и `flash-ring` используют Strata; раскладка устройств и режимы 27B сохранены.
Новые aliases используют собственный `{runtime_kv}`; native checkpoints к ring
не подключаются. Порты на Aurora: Strata plain 18201, Strata ring 18200; на .173 ring — 18198 (loopback).

- Flash plain: upstream Strata v0.1.40 HTTP server, IQ4_XS, INT8 KV, MTP4,
  Cyrillic draft vocabulary, 128K, один слот. Компактизацией управляет Nemor.
- Flash ring: наш native Strata runner, те же веса/KV/MTP, 128K, два RAM-слота,
  trigger98304, keep65536, summary512. Поддерживает text/tools, фоновые summary,
  `context_state` и атомарные KV checkpoints через llm-proxy.
  Изображения пока не поддерживаются в обоих новых профилях; старые llama.cpp
  runtime и их KV-кэш сохранены отдельно. Длинный диалог с изображениями нельзя
  автоматически перенести в Strata вместе с прежним KV.
- 27B: .173, существующая CUDA-сборка `~/project/llama-ring-vision-20261008`,
  Q4_K_M + vision-f16, Q8 KV, P24576, summary8192, max-output16000,
  MTP3, CPU projector с image-max-tokens1024. Окно 114688 соответствует
  установленному `vcortex-shadow`. Этот прежний runtime включён в `managed`:
  при переключении его on-demand запуск отключается, освобождая GPU.

Сначала подготовить два профиля на Nemor, локально клонируя токены и TLS pin:

```sh
ssh mirmik@192.168.0.76 python3 - < deploy/model-layout/prepare_profiles.py
```

Скрипт не меняет персонажей, не печатает секреты и не перезаписывает существующие
профили. При несовпадении server/model/id требуется сначала исправить профиль.
Runtime добавляются в proxy-конфигурации при первом `switch`.

Перед обновлением установленной утилиты убедиться, что её журнал имеет статус
`complete`, `rolled_back` или `aborted`, и нет текущего переключения. Сохранить
резервную копию `~/.local/share/model-layout`, затем перенести туда файлы
`model-layout`, `model_layout.py`, `remote.py`, `layouts.yaml`, `README.md`,
`prepare_profiles.py`. Проверить `model-layout plan flash-ring` и
`model-layout plan 27b-ring`.

Проверка 2026-10-09: семь тестов с временными файлами и имитацией служб покрывают
четыре режима, no-op, read-only plan, обратное переключение настроек, полный
rollback и отказ затирать посторонние правки. На трёх реальных узлах проверен
preflight. Полный цикл загрузки GPU через новые режимы этой проверкой не выполнялся.

## Переход Flash на Strata (2026-10-10)

Runtime `flash-next-strata` и `flash-next-strata-ring` зарегистрированы отдельно,
с `autoload=false`, `on_demand=false` до явного переключения. Их определения
хранятся также в `vcortex/strata-ring/deploy/`. Новые Nemor profiles
`model-flash-strata` и `model-flash-strata-ring` клонируют авторизацию существующего
Flash profile на самом узле .76. Старые profiles не перезаписываются.

`model-layout switch flash` запускает обычную Strata; `model-layout switch flash-ring`
запускает Strata с нашей компактизацией. Старые Flash runtime остаются в `managed`,
поэтому переключатель останавливает их и отключает автоматический запуск.
Изменение конфигурации режимов само по себе не перезапускает текущую сессию Nemor.

Оба Strata-профиля теперь включают изображения: CPU `strata-vision` +
`mmproj-F16.gguf`, до 1024 visual tokens на картинку. Ring сохраняет embeddings
в checkpoint и учитывает M-RoPE при кольцевом сжатии. Проверка —
`vcortex/experiments/064-strata-vision.md`.

2026-10-11: Strata flash/flash-ring возвращены на единое окно 262144 токена,
как у прежнего Flash-профиля. В Strata удалён отдельный лимит длины резюме;
вставляется только его текст. Старые 128K KV-checkpoints сохранены отдельно.
